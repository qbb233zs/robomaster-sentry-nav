## 1. 开机前检查

### 1.1 硬件

- [ ] 工控机、雷达、电控都已供电。
- [ ] 雷达网线插在正确的有线网口（当前常用 `enp3s0`）。
- [ ] CH340 串口模块插在正确的 USB 口（目标是物理口 `1-3`）。
- [ ] 串口接线为交叉接法：`TXD -> RX`、`RXD -> TX`、`GND -> GND`。
- [ ] 第一次上电或换线后，车最好架起来，轮子离地。
- [ ] 周围没有会绊住线缆、车体或云台的物品。

### 1.2 网络

```bash
ip -br addr show enp3s0
# 期望看到：192.0.2.10/24

ping -c 2 192.0.2.175
# 192.0.2.x 仅为公开文档示例地址，现场以实际雷达 IP 为准
```

如果 IP 不通，先查网线、网口和雷达供电，不要先启动导航。

跑导航前关闭 Livox Viewer，否则可能和 ROS 驱动抢端口。

### 1.3 串口

```bash
ls -l /dev/rm_serial /dev/ttyUSB* 2>&1
```

正常应看到类似：

```text
/dev/rm_serial -> ttyUSB0
/dev/ttyUSB0
```

如果 `/dev/rm_serial` 不存在，先确认哪个 USB 是底盘串口：

```bash
lsusb | grep -i '1a86\|ch34'
for d in /dev/ttyUSB*; do
  echo "== $d"
  udevadm info -q path -n "$d"
done
```

当前 udev 规则：

```text
物理口 1-3 的 CH340 -> /dev/rm_serial
物理口 1-6 的板载 CH340 -> 已屏蔽
```

规则文件：

```text
/etc/udev/rules.d/99-rm-serial.rules
/etc/udev/rules.d/98-block-usb-serial-1-6.rules
```

临时兜底（只在确认 `ttyUSB0` 就是底盘串口时使用）：

```bash
sudo ln -sf /dev/ttyUSB0 /dev/rm_serial
sudo chmod 666 /dev/ttyUSB0
```

不要同时打开 VOFA+、串口助手、minicom 等程序占用同一个串口。串口桥运行期间，`/dev/rm_serial` 应归串口桥占用。

### 1.4 清理上一场残留

先查看，不要一上来就 `pkill -9`：

```bash
ps -ef | grep -E 'ros2|rviz2|component_container|pointlio|livox|slam_toolbox|rm_serial|rm_behavior' | grep -v grep
```

确认是本项目的残留后，优先在各个终端按 `Ctrl+C`。必须强杀时再按进程名处理。

## 2. 方案 A：RViz 手动目标点导航

这是最基础、最重要的验收流程。先保证这一套能稳定工作，再做决策树。

### 2.1 终端 1：串口桥

```bash
source /opt/ros/humble/setup.bash
source /home/robot/CCUTVision/install/setup.bash
ros2 launch rm_serial_driver serial_driver.launch.py
```

期望日志：

```text
Start RobotMasterSerialDriver!
cmd_vel yaw offset: 90.0 deg
gimbal_joint_state_relay started
Device name is FORCE SET to: /dev/rm_serial
```

这个 launch 会同时启动：

- `rm_serial_driver_node`：收发速度帧，并订阅 `/red_standard_robot1/cmd_vel`
- `gimbal_joint_state_relay`：把 `/robot_yaw` 转成 `/red_standard_robot1/serial/gimbal_joint_state`

不允许出现：

```text
Watchdog timeout! No vision packet for 1.00 seconds.
KILLING NODE TO RESTART!
```

出现 `Watchdog timeout` 说明电控没有在 1 秒内回传姿态帧，或者串口线/端口不对。此时串口桥会主动退出，必须先修这个问题。

### 2.2 终端 2：真机导航

  namespace:=red_standard_robot1 \
  world:=lab9 \
  slam:=False \
  use_sim_time:=False \
  use_robot_state_pub:=True \
  use_rviz:=True

必须注意：

- `world:=lab9` 必须和 `map/reality/lab9.yaml`、`pcd/reality/lab9.pcd` 对应。
- 不要写成 `namespace=red_standard_robot1`，launch 参数必须是 `:=`。
- 实车 `use_sim_time:=False`。
- RViz 崩溃时导航节点不一定跟着崩；先看终端是否还活着，不要盲目重启整个车。

## 3. 方案 B：决策树自动巡逻/回家

### 3.1 启动顺序

终端 1、终端 2 和方案 A 完全一样：

1. 串口桥
2. 真机导航

然后启动虚拟裁判和行为树。

### 3.2 终端 3：虚拟裁判

```bash
source /opt/ros/humble/setup.bash
source /home/robot/nav-master-ccut-WCZ-newcccutNav2/nav-master-ccut/install/setup.bash
source /home/robot/nav-master-ccut-WCZ-newcccutNav2/rm_decision/install/setup.bash

ros2 run rm_decision robot_status_publisher --ros-args \
  -p mode:=4 \
  -p init_hp:=600 \
  -p update_rate_hz:=2
```

`mode` 含义：

| mode | 行为 | 用途 |
|---:|---|---|
| 1 | HP 在 500~600 之间来回波动 | 只维持高血量，不会自动触发回家 |
| 2 | HP 逐渐下降，到 100 重置 600 | 单纯掉血测试 |
| 3 | HP 在 300~600 随机跳变 | 随机状态测试 |
| 4 | 600 掉到 300，停 20 秒，再回血到 600，循环 | **验证回家/巡逻切换，用这个** |

> 之前“虚拟裁判不扣血/不回家”的常见原因是用 mode 1。mode 1 最低只到 500，决策树的回家线是 300，所以永远不会触发。

### 3.3 终端 4：行为树

```bash
source /opt/ros/humble/setup.bash
source /home/robot/nav-master-ccut-WCZ-newcccutNav2/nav-master-ccut/install/setup.bash
source /home/robot/nav-master-ccut-WCZ-newcccutNav2/rm_decision/install/setup.bash

ros2 launch rm_behavior_tree rm_behavior_tree.launch.py \
  style:=full_decision \
  use_sim_time:=False
```

> **必须写 `use_sim_time:=False`。**  
> `rm_behavior_tree.launch.py` 的默认值是 `True`，直接启动会让实车行为树时间源不对。

### 3.4 当前决策树逻辑

文件：

```text
/home/robot/nav-master-ccut-WCZ-newcccutNav2/rm_decision/src/rm_behavior_tree/config/full_decision.xml
```

当前逻辑：

```text
HP 高于阈值：巡逻
  PatrolGoal = -5.00;3.20;0;0;0;0;1

HP 降到 300 及以下：回家
  HomeGoal = 0.00;0.00;0;0;0;0;1

HP 回到 350 以上：重新巡逻
```

注意：

- 这两个坐标是 `lab9` 当前使用的点，**不一定适合你重新扫描的新地图**。
- 换地图后，必须重新从 RViz 取点，并修改 `full_decision.xml`。
- `0.00;0.00` 只有在“新地图原点就是你想当作家的位置”时才有效。
- XML 在本机是软链接进 `install` 的，改完通常重启行为树即可；如果不确定，重新编译 `rm_decision`。

### 3.5 成功标准

- [ ] 终端 3 的 HP 能从 600 降到 300。
- [ ] HP 到 300 时，行为树终端出现切到 `HomeGoal` 的日志。
- [ ] 车从巡逻点向家点移动，导航目标确实切换。
- [ ] HP 回血到 350 以上后，行为树重新切回 `PatrolGoal`。
- [ ] 整个过程中串口桥没有退出，车不是只原地自转。

## 6. 串口桥和速度单点测试

这一节用于“导航还没开，只想验证串口和轮子”的台架测试。

### 6.1 只启动串口桥

```bash
source /opt/ros/humble/setup.bash
source /home/robot/CCUTVision/install/setup.bash
ros2 launch rm_serial_driver serial_driver.launch.py
```

把车架起来，遥控器切 `UP` 导航模式，然后另开终端发一个很小的前进速度：

```bash
source /opt/ros/humble/setup.bash
ros2 topic pub -r 20 /red_standard_robot1/cmd_vel \
  geometry_msgs/msg/Twist \
  "{linear: {x: 0.10, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}" \
  --times 40
```

这段命令发 2 秒左右的小速度。观察：

- 串口桥有没有收到并发送速度；
- 轮子是否按预期动作；
- 是否有异常声音、堵转、线缆拉扯。

> 不要在导航 launch 同时运行时做这个测试。导航也会发布 `/red_standard_robot1/cmd_vel`，两个发布者会互相打架。

### 6.2 串口方向核对

当前串口驱动在发送前做 90° 旋转：

```text
串口 x = -ROS y
串口 y =  ROS x
```

对应配置：

```text
/home/robot/CCUTVision/src/rm_serial_driver/config/serial_driver.yaml
cmd_vel_yaw_offset_deg: 90.0
```

如果电控再次修改 x/y 定义，先只改这一处并在台架上验证，不要同时改 `fake_vel_transform`、导航参数和串口桥三处。

### 6.3 视觉链路（独立测试，不是导航必需）

## 7. 常见故障对照

| 现象 | 优先检查 | 处理 |
|---|---|---|
| `/dev/rm_serial` 不存在 | USB、`lsusb`、`udevadm info` | 确认插在 1-3；必要时临时链接 `ttyUSB0` |
| 串口桥报 `Watchdog timeout` | 电控是否回传姿态帧、TX/RX/GND、串口是否被占用 | 先修电控回传/串口，不能继续导航 |
| 车只自转、不平移 | 导航模式自转正常；看 `cmd_vel` 是否有非零 `vx/vy` | 若 `cmd_vel` 全 0，查 Nav2；若有速度但不动，查串口方向和电控 |
| `cmd_vel` 有数据但车完全不动 | 串口桥日志、90° 偏移、电控固件 | 先用单点测试发 `vx=0.10`，确认轮子 |
| 发目标点后 `/cmd_vel` 一直 0Hz | 地图、lifecycle、TF、控制器 | 看导航终端和 `goal_watch.py`，先从 `plan` 环节查 |
| RViz 没有 `map` | `map_server`、命名空间、地图文件 | 确认 `world:=lab9` 和 `map/reality/lab9.yaml` 存在 |
| `map -> base_footprint` TF 查不到 | TF 话题重映射、robot_state_publisher、定位链 | 用命名空间 TF remap 检查，不要只看全局 `/tf` |
| 目标点在障碍物里，车不走 | 目标点落在占用格/膨胀区 | 换一个空闲点，必要时检查 `inflation_radius` |
| 决策树不触发回家 | 虚拟裁判模式 | 测试回家必须用 `mode:=4`，不是 `mode:=1` |
| 决策树目标点跑到地图外 | XML 还是旧地图坐标 | 用 `Publish Point` 重新取点并修改 XML |
| 导航出现 `local_plan stamp is ...` | `fake_vel_transform`/控制器时间戳修复是否是最新编译 | 确认使用 2026-10-18 之后的安装；反复出现就保留日志排查 |
| 导航出现 `can't subtract times` | ROS 时间源混用 | 确认 `use_sim_time:=False`，并检查是否为最新编译 |
| RViz 卡死/崩溃 | RViz 本身或组件容器 | 先看导航终端是否还活；组件容器死了才重启导航 |
| 串口桥和视觉同时抢串口 | 两个节点都订阅/打开同一设备 | 导航串口桥运行时，不要启动另一个串口驱动 |

## 9. 停机和急停

### 9.1 正常停机

建议顺序：

1. 先按 `Ctrl+C` 停决策树。
2. 再按 `Ctrl+C` 停虚拟裁判。
3. 再按 `Ctrl+C` 停导航。
4. 最后按 `Ctrl+C` 停串口桥。

### 9.2 急停

```text
第一优先：遥控器左拨杆 DOWN（底盘失能）
第二优先：Ctrl+C 串口桥
第三优先：Ctrl+C 导航
```

不要为了“先看日志”而让车继续朝线缆、人或其他设备移动。

### 9.3 如果必须重启

1. 遥控器 `DOWN`。
2. 停掉所有终端节点。
3. 检查 `/dev/rm_serial`、雷达 ping、地图文件。
4. 重新按方案 A 的终端顺序启动。
5. 先点一个近距离、空地上的目标点，确认能走，再点远点。
