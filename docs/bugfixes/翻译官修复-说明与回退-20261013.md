# 翻译官(pointcloud_to_laserscan) tf2 死锁修复 — 说明与回退

日期：2026-10-13
文件：src/rm_perception/pointcloud_to_laserscan/src/pointcloud_to_laserscan_node.cpp

## 一、问题现象
建图/导航时 `/red_standard_robot1/obstacle_scan` 偶发 0Hz、不自愈，
上游 terrain_ext 正常，导致 /map 冻结、建图中断（“建图一直失败”）。

## 二、根因（gdb 实证）
ROS Humble 的 tf2_ros 0.25.23 里，MessageFilter 的 futures 等待
(`Buffer::waitForTransform`) 与 TransformListener 的测试线程发生 AB-BA 死锁：
- 主线程持 `timer_to_request_map_mutex_` 等 `transformable_requests_mutex_`
- TF 线程持 `transformable_requests_mutex_` 完成回调里等 timer 锁
两把锁互等，进程静默卡死。5 份台架现场栈签名一致，owner 交叉印证。
证据目录：outputs/deadlock_evidence/

## 三、修复内容（两处）
1) target_frame 非空时不再创建 MessageFilter，改为直接订阅 + 回调里转型；
2) 回调转型改成两段式：
   - 先按原有 `transform_tolerance`(默认0.01s) 等精确时刻的 TF；
   - 等不到时，用“最新可用 TF”兜底（TF 年龄 < 0.25s 才用，超过就丢帧），
     避免 TF 比点云晚几百微秒时整帧被丢（台架曾因此丢掉 2/3 帧）。

备份（同目录）：
- `pointcloud_to_laserscan_node.cpp.bak-tf2fix-20261013`  原始文件
- `pointcloud_to_laserscan_node.cpp.bak-tf2fix2-20261013` 仅第1步修改

## 五、台架验证（假点云 100k点 + 假 TF，每40秒断 TF 2 秒）
| 版本 | 结果 |
|---|---|
| 原版(MessageFilter) | 3 秒内必卡死，obstacle_scan 归零 |
| 修复版 | 连续 650 秒：0 卡死 / 0 重启 / 0 Transform failure |
| 修复版帧率 | 6min 稳定段：入7.98/出7.91Hz（≈1:1）；瞬时最小间隔0.123s（≈8.1Hz）|

注：每 40 秒的 TF 断供是台架“故意制造”的极端工况，断供超过 0.25s 后
按设计丢帧，断供结束即恢复。日志：outputs/p2l_repro/rig83_logs/
