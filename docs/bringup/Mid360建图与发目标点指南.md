# Mid-360 扫实验室 → RViz 发目标点 → "高度"过滤小球：操作手册

> 对应任务：用 Mid-360 扫描实验室建图，装到哨兵上，在 RViz 里指定目标点让车过去，并设置"高度"让地上的小球不被当成障碍物。
> 本文所有路径都基于当前这台机器（robot@robot-MIX-NUC-II）。行号以当前文件为准，文件被改动后请以实际内容为准。
>
> 公开版说明：内网地址已替换为 `192.0.2.x` 文档示例地址。本文保留早期调试思路，雷达最终安装位置、TF 父子关系和启动参数以 `docs/operations/哨兵机器人运行方案.md` 为准。

## 0. 先看懂整条链路（一句话 + 一张图）

```
Mid-360 雷达
   │ 网线（点云 20Hz + IMU）
   ▼
livox_ros_driver2 驱动        → 话题 /livox/lidar、/livox/imu
   ▼
point_lio（激光惯性里程计）    → 里程 odom、点云 cloud_registered
   ▼
loam_interface               → registered_scan、lidar_odometry
   ▼
terrain_analysis / _ext      → 把每个障碍点"离地高度"写进 intensity → terrain_map、terrain_map_ext
   ▼
nav2 costmap（强度体素层）     → 只把高度合适的点画成障碍物
   ▼
规划器 Theta* + 控制器        → /red_standard_robot1/cmd_vel
   ▼
串口桥 rm_serial_driver       → 19 字节速度帧 → 电控 STM32 → 轮子
```

两种模式：
- **建图模式 `slam:=True`**：slam_toolbox 实时拼 2D 栅格图（pgm/yaml）；point_lio 在退出时把 3D 点云存成 `scans.pcd`。
- **导航模式 `slam:=False`**（默认）：map_server 加载 pgm+yaml，small_gicp 加载 pcd 重定位，然后在 RViz 点目标点。

## 1. 接线与联网（雷达）

| 接什么 | 怎么接 |
|---|---|
| 网线 | 雷达网口 → 主机有线口（`enp3s0`，或 USB 网卡 `enx76cc2934dacf`） |
| 电源 | 雷达单独供电 9~27V（**不走网线供电**） |
| 安装位置 | 最终实车以机械设计和 TF 配置为准；本文早期版本曾按雷达固定在车体上调试 |

主机和雷达必须处于同一网段。下面使用 `192.0.2.x` 作为公开文档示例地址（雷达地址写在 `mid360_user_config.json` 里）：

```bash
sudo nmcli con add type ethernet ifname enp3s0 con-name lidar ipv4.method manual ipv4.addresses 192.0.2.10/24
sudo nmcli con up lidar
# 如果提示 already exists：把 add 换成 mod（sudo nmcli con mod lidar ipv4.addresses 192.0.2.10/24）再 up

ip -br addr show enp3s0    # 确认主机地址已配置
ping 192.0.2.175           # 通 = 雷达在线（地址按现场替换）
```

单独验证雷达（先不启动导航）：

```bash
source /opt/ros/humble/setup.bash
source ~/nav-master-ccut-WCZ-newcccutNav2/nav-master-ccut/install/setup.bash
ros2 launch livox_ros_driver2 msg_MID360_launch.py
# 另开一个终端：
ros2 topic hz /livox/lidar     # 应该 ~10Hz
ros2 topic hz /livox/imu
```

注意：跑 ROS 驱动前先关掉 Livox Viewer（桌面"Livox 雷达查看器"），两个同时开会抢端口。

## 2. 建图（SLAM 模式）

**终端 A：**

```bash
source /opt/ros/humble/setup.bash
source ~/nav-master-ccut-WCZ-newcccutNav2/nav-master-ccut/install/setup.bash

ros2 launch rm_nav_bringup rm_navigation_reality_launch.py \
  slam:=True use_robot_state_pub:=True namespace:=red_standard_robot1
```

**终端 B（确认数据真在流）：**

```bash
ros2 topic hz /red_standard_robot1/livox/lidar        # ~20Hz
ros2 topic hz /red_standard_robot1/livox/imu
ros2 topic hz /red_standard_robot1/terrain_map_ext    # 走过障碍物时才有意义
```

- 推着车走或电控用遥控器慢慢开，**速度 < 0.5 m/s，转弯要慢**，绕场一圈回到起点再停（让 slam_toolbox 闭个环）。
- RViz 里看地图一点点长出来（Fixed Frame 已是 `map`）。

**存图（终端 C，趁建图还开着）：**

```bash
ros2 run nav2_map_server map_saver_cli -f ~/lab --ros-args -r __ns:=/red_standard_robot1
# 生成 ~/lab.pgm 和 ~/lab.yaml
```

**回终端 A 按 Ctrl+C 停掉（必须 Ctrl+C，point_lio 在退出那一刻才写 pcd），然后检查：**

```bash
ls -l ~/lab.pgm ~/lab.yaml
ls -l ~/nav-master-ccut-WCZ-newcccutNav2/nav-master-ccut/src/rm_localization/point_lio/PCD/scans.pcd
```

## 4. 导航模式 + RViz 发目标点

**终端 1：串口桥（和以前联调一样）**

```bash
source /opt/ros/humble/setup.bash
source ~/CCUTVision/install/setup.bash
ros2 launch rm_serial_driver serial_driver.launch.py
```

**终端 2：导航**

```bash
source /opt/ros/humble/setup.bash
source ~/nav-master-ccut-WCZ-newcccutNav2/nav-master-ccut/install/setup.bash

ros2 launch rm_nav_bringup rm_navigation_reality_launch.py \
  world:=lab slam:=False use_robot_state_pub:=True namespace:=red_standard_robot1
# 没把图拷进工程的替代写法：
#   ... map:="$HOME/lab.yaml" prior_pcd_file:"$HOME/lab.pcd"
```

**RViz 操作：**

1. 等 `Global Status: Ok`，地图出现、车的位置正确（车要放在**建图起点附近、朝同一方向**，small_gicp 才容易对上）。
2. 工具栏选 **2D Goal Pose**（就是"指定目标点"）。
3. 在图上点目标位置，按住拖出箭头表示车到达时的朝向，松手。
4. 车会自己规划路径、遇到障碍物绕过去；想验证有没有在发速度：
   ```bash
   ros2 topic hz /red_standard_robot1/cmd_vel
   ```
   串口桥终端里会看到 `TX twist: ...`。

**前提提醒（和之前联调一致）：** 遥控器开机、左拨杆最上 UP（导航模式），电控在线，否则电控不接速度。

## 5. 学长说的"设置一个高度" —— 具体是哪个参数

原理：`terrain_analysis` 把每个障碍点的**离地高度**写进点云的 `intensity` 字段；
代价地图的强度体素层（`IntensityVoxelLayer`）只把 intensity 在
`[min_obstacle_intensity, max_obstacle_intensity]` 之间的点当成障碍物。

**文件：** `~/nav-master-ccut-WCZ-newcccutNav2/nav-master-ccut/src/rm_nav_bringup/config/reality/nav2_params.yaml`

| 行号 | 参数 | 当前值 | 含义 |
|---|---|---|---|
| 411 | `min_obstacle_height`（局部代价地图） | 0.0 | costmap 坐标系里低于此高度的点忽略 |
| 413 | `min_obstacle_intensity`（局部代价地图） | 0.1 | **离地高度 < 0.1m 的点不当障碍物** ← 小球就是被这个挡住的 |
| 459 | `min_obstacle_height`（全局代价地图） | 0.0 | 同上，管规划器绕远路 |
| 461 | `min_obstacle_intensity`（全局代价地图） | 0.1 | 同上 |

小球（几厘米高）本来就低于 0.1，应该已经被过滤；**如果现场发现小球还是被当成障碍物**，
把 413 和 461 两行的 `0.1` 改成 `0.15` 或 `0.2`，保存后**重启导航 launch**（参数只在启动时读一次）。
yaml 是软链接进 install 的，**不用重新编译**。

注意：
- 别调太高（不要超过 0.3）：门槛、线缆、地面杂物也会看不见，车会压上去。
- 这只管"实时避障"。**保存的 2D 地图**里有没有小球，取决于建图时 `pointcloud_to_laserscan` 的
  `min_intensity: 0.1`（第 187 行），道理一样，一般不用改。
- `terrain_analysis` 的 `vehicleHeight: 0.5`（第 126 行）表示只把离地 0.5m 以下的点送进地形图
  （墙、桌腿的"下部"点也会进来），**不要动它**。

## 6. 检查清单（出问题先看这里）

| 现象 | 大概率原因 |
|---|---|
| `ping 192.0.2.175` 不通 | 网线/网口不对、主机与雷达不在同一网段、雷达没供电 |
| `ros2 topic hz /livox/lidar` 无数据 | 雷达没供电、IP 不对、Livox Viewer 还开着抢端口 |
| RViz 里地图不动 / 车位置乱跳 | 点云或 IMU 没进来、雷达被云台带着转（装错位置） |
| `map_saver_cli` 保存出来是空的 | 建图 launch 没起来、`__ns` 不对 |
| `scans.pcd` 没有/时间不对 | 建图时没按 Ctrl+C 正常退出 |
| 导航发目标点车不动 | 串口桥没开/死了、遥控没切导航模式、`/red_standard_robot1/cmd_vel` 没数据 |
| 车到了目标点附近原地不转 | 正常（这台车配置 `yaw_goal_tolerance: 6.28`，对最终朝向要求很松） |

## 8. 雷达平装改动记录（2026-10-07）

把雷达从斜装改为**平装（0°）**，共改 2 个文件；桌面测试已验证：点云/桌面恢复水平，不再整体倾斜。

**规律（2026-10-07 晚更正，已对照 point_lio 源码 `rm_localization/point_lio/src/laserMapping.cpp` 初始化段与 `IMU_Processing.cpp` 的 `Set_init/IMU_init`）：**

系统里有 **两处** 和"雷达姿态"有关，但管的事不一样：

| 位置 | 文件 | 现值（平装） | 含义 |
|---|---|---|---|
| ① 模型安装角 | `src/pb2025_robot_description/resource/xmacro/pb2025_sentry_robot.sdf.xmacro`（第 25 行 livox 那行 pose 末尾） | `0.0496 0.0936 0.435 0 0 0` | **必须等于实物安装角**：平装填 0，斜装填那个斜角 |
| ② point_lio 重力方向 | `src/rm_nav_bringup/config/reality/nav2_params.yaml`（第 67、68 行） | `[0.0, 0.0, -0.9921428427722313]` | **世界系重力方向，永远竖直向下，不是安装角** |

- 上次"只改一处 = 画面还是歪"，是因为当时 ① 是 -15°、② 里又存着 32° 的斜值，两个都有问题；把 ② 改回竖直本身就是必须做的修复（斜值会把整个世界坐标系带歪 → 地图整体斜）。
- 以后真要斜装：**只改 ①**（两个文件在 install 里都是软链接，改完不用编译，重启 launch 即生效，重启后先放平稳 1~2 秒再动）；**② 保持竖直，不要动** —— 物理上怎么装，point_lio 在 `imu_en: True` 时用开机静置的 IMU 平均加速度自己测出来。
- `extrinsic_R/T`（`nav2_params.yaml` 第 69、70 行）是雷达和它内置 IMU 之间的固定关系，任何情况下都不要改。
- 旧值（斜装时代）：① `-${pi/12}`（-15°）；② `[0.0, 0.5305473804473877, -0.8383715748786926]`（约 32°）。其中 ② 的斜值是"小车和地图一直斜着"的主因（它必须竖直）。
- 改完（尤其斜装时）做静止验证：放平稳重启，桌面/地面应是平的；不平再核对 ① 的轴向与正负号。
