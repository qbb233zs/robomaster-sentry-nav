# v3.0 修改记录

> 基线版本：`v2.1`  
> 本版版本：`v3.0`  
> 路径基准：压缩包根目录 `nav-master-ccut-WCZ-newcccutNav2/` 和 `rm_decision/`  
> 比对口径：比较解压后的源码快照，排除构建目录和手工备份。本文只记录本版相对 v2.1 的真实源码差异。

## 1. 本版结论

本版只修改了决策树相关代码，共 2 个业务源码文件：

1. `rm_decision/src/rm_behavior_tree/config/full_decision.xml`
2. `rm_decision/src/rm_behavior_tree/src/plugins/action/send_goal.cpp`

本版主要解决以下问题：

- 低血回家后，血量刚恢复到旧阈值 `350` 就过早切回巡逻；
- 巡逻目标点仍是旧场地坐标 `-5.00,3.20`；
- Nav2 在距离目标约 `0.10 m` 处持续微调时没有及时返回结果；
- 决策树在 Nav2 停止反馈或一次导航失败时可能中断；
- `SendGoal` 已经声明了近目标状态变量，但 v2.1 没有真正使用。

本版没有修改 small-GICP 主源码。快照里出现的 GICP `.bak` 文件只是备份，不是 3.0 的功能改动。

## 2. 修改文件总览

| 文件 | 本版变化 |
|---|---|
| `rm_decision/src/rm_behavior_tree/config/full_decision.xml` | 回血阈值改为 `580`；巡逻目标改为 `2.376,0.066`；两个导航目标增加 45 秒内外两层超时；回家分支增加无限重试 |
| `rm_decision/src/rm_behavior_tree/src/plugins/action/send_goal.cpp` | 新增“距离目标 0.20 m 以内并稳定 1 秒即判定到达”的逻辑 |

## 3. `full_decision.xml` 修改

文件路径：

```text
rm_decision/src/rm_behavior_tree/config/full_decision.xml
```

### 3.1 回血后切回巡逻的阈值从 350 改为 580

修改前：

```xml
<IsStatusOK name="CheckHP" low_hp="300" high_hp="350" robot_status="{robot_status}"/>
```

修改后：

```xml
<IsStatusOK name="CheckHP" low_hp="300" high_hp="580" robot_status="{robot_status}"/>
```

行为变化：

- 血量 `<= 300` 时切到回家分支；
- 回家过程中只有当血量 `> 580` 时才重新切回巡逻；
- 不会出现血量刚回到 350 左右就马上离开家、再次等到低血才回家的状态抖动。

新增注释也同步把“目标执行期间最多 30 秒”改成了“最多 45 秒”，与后面的超时配置一致。

### 3.2 巡逻目标点改为实验室目标

修改前：

```xml
<SendGoal name="PatrolGoal" timeout="30"
          goal_pose="-5.00;3.20;0;0;0;0;1"
          action_name="/red_standard_robot1/navigate_to_pose"/>
```

修改后：

```xml
<SendGoal name="PatrolGoal" timeout="45"
          goal_pose="2.376;0.066;0;0;0;0;1"
          action_name="/red_standard_robot1/navigate_to_pose"/>
```

坐标格式为：

```text
x;y;z;qx;qy;qz;qw
```

因此本版巡逻点为：

```text
x = 2.376
y = 0.066
z = 0
姿态四元数 = (0, 0, 0, 1)
```

### 3.3 回家目标点没有变

回家目标仍然是：

```xml
goal_pose="0.00;0.00;0;0;0;0;1"
```

本版只改了巡逻点，没有改回家点。

### 3.4 两个导航目标增加外层 `Timeout`

巡逻分支修改后：

```xml
<RetryUntilSuccessful num_attempts="-1">
  <Timeout msec="45000">
    <SendGoal name="PatrolGoal" timeout="45"
              goal_pose="2.376;0.066;0;0;0;0;1"
              action_name="/red_standard_robot1/navigate_to_pose"/>
  </Timeout>
</RetryUntilSuccessful>
```

回家分支修改前：

```xml
<SendGoal name="HomeGoal" timeout="30"
          goal_pose="0.00;0.00;0;0;0;0;1"
          action_name="/red_standard_robot1/navigate_to_pose"/>
```

回家分支修改后：

```xml
<RetryUntilSuccessful num_attempts="-1">
  <Timeout msec="45000">
    <SendGoal name="HomeGoal" timeout="45"
              goal_pose="0.00;0.00;0;0;0;0;1"
              action_name="/red_standard_robot1/navigate_to_pose"/>
  </Timeout>
</RetryUntilSuccessful>
```

两层超时的职责不同：

- `SendGoal` 的 `timeout="45"`：作为 action 节点自身记录的内部超时，在收到 feedback 时检查总耗时；
- 外层 `<Timeout msec="45000">`：即使 Nav2 卡住到完全不返回 feedback，BT 也会在 45 秒后结束该子树；
- `RetryUntilSuccessful num_attempts="-1"`：失败或超时后无限重试，避免一次规划失败直接把整棵树打穿。

### 3.5 修改后的完整决策结构

```text
ReactiveSequence
├── SubRobotStatus
└── ReactiveFallback
    ├── 高血分支 ReactiveSequence
    │   ├── IsStatusOK(low_hp=300, high_hp=580)
    │   └── RetryUntilSuccessful(无限)
    │       └── Timeout(45000 ms)
    │           └── PatrolGoal(2.376, 0.066, 45 s)
    └── 低血分支 RetryUntilSuccessful(无限)
        └── Timeout(45000 ms)
            └── HomeGoal(0.000, 0.000, 45 s)
```

## 4. `send_goal.cpp` 修改

文件路径：

```text
rm_decision/src/rm_behavior_tree/src/plugins/action/send_goal.cpp
```

### 4.1 新增近目标到达判定

在 `onFeedback()` 中，日志输出之后、全局超时判断之前，新增：

```cpp
// Nav2 有时会在距离目标几厘米处一直旋转/微调，既不报成功也不报失败。
// 这里把"稳定 1 秒都在 0.20 m 以内"视为到达，避免外部 BT 超时后
// 取消一个实际上已经完成的目标。
constexpr double kGoalReachedDistance = 0.20;
constexpr double kGoalReachedHoldSeconds = 1.0;
if (dist <= kGoalReachedDistance) {
    if (!in_small_region_) {
        in_small_region_ = true;
        small_region_start_ = now;
    } else if ((now - small_region_start_).seconds() >= kGoalReachedHoldSeconds) {
        RCLCPP_INFO(
            node_->get_logger(),
            "[%s] Goal treated as reached: distance_remaining=%.2f m for >= %.1f s",
            name().c_str(), dist, kGoalReachedHoldSeconds);
        setLastReachedGoal(goal_key_);
        return BT::NodeStatus::SUCCESS;
    }
} else {
    in_small_region_ = false;
}
```

### 4.2 判定逻辑

判定条件不是“只要进过一次 0.20 m 就成功”，而是：

1. 收到 Nav2 action feedback；
2. `distance_remaining <= 0.20 m` 时，开始计时；
3. 连续 1 秒内每次 feedback 都仍然不大于 0.20 m；
4. 满足 1 秒后，调用 `setLastReachedGoal(goal_key_)`；
5. `onFeedback()` 返回 `BT::NodeStatus::SUCCESS`。

如果中途某次 feedback 的距离大于 0.20 m：

```cpp
} else {
    in_small_region_ = false;
}
```

计时会被取消，下次再进入 0.20 m 时需要重新连续保持 1 秒。

### 4.3 为什么不直接降低 Nav2 goal tolerance

这个 0.20 m 是决策树 action 插件层的“结果确认阈值”，不是 Nav2 全局目标容差参数，也不修改 costmap 或控制器参数。它只解决以下衔接问题：

```text
Nav2 已经基本到达，但 action result 迟迟不返回
  -> 决策树认为目标仍在 RUNNING
  -> 外层 45 秒超时后取消目标
  -> 目标被重复下发/巡逻被误打断
```

v3.0 改为在决策层确认“已经靠近且稳定”，避免取消实际上已经完成的目标。

### 4.4 与已有重复目标保护的关系

`setGoal()` 中已有相同目标跳过的逻辑。本版在近目标到达时写入：

```cpp
setLastReachedGoal(goal_key_);
```

这样当决策树尚未切换分支、再次下发完全相同目标时，已有的 `skip_duplicate_` 机制会跳过重复动作，不会因为“近目标也报成功”而产生立即重复导航。

## 5. 行为影响

### 5.1 正常低血回家流程

```text
HP <= 300
  -> 取消巡逻
  -> 下发 HomeGoal(0.00, 0.00)
  -> 离目标 <= 0.20 m 并稳定 1 s：决策树判定到达
  -> 继续施救/回血
  -> HP > 580
  -> 切回 PatrolGoal(2.376, 0.066)
```

### 5.2 Nav2 靠近目标但不返回结果

```text
Nav2 feedback 持续显示 distance_remaining 约 0.10 m
  -> 0.20 m 内连续 1 s
  -> SendGoal 主动返回 SUCCESS
  -> 不再等待 Nav2 自己返回 action result
```

### 5.3 完全收不到 feedback

```text
SendGoal 卡住且没有任何 feedback
  -> SendGoal 内部 timeout 无法在 onFeedback 中检查
  -> 外层 BT Timeout 在 45000 ms 后结束该节点
  -> RetryUntilSuccessful 重新尝试
```
