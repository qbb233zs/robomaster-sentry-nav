# v2.0 修改记录

> 基线版本：`v1.1`  
> 本版版本：`v2.0`  
> 路径基准：压缩包根目录 `nav-master-ccut-WCZ-newcccutNav2/`  
> 比对口径：比较解压后的源码快照，排除构建目录和手工备份。本文只记录本版相对 v1.1 的真实源码差异。

## 1. 本版结论

本版共修改 2 个业务源码文件，核心是两件事：

1. 修正 `fake_vel_transform` 中 local plan、里程计和控制激活时间的时间域与过期判断；
2. 修正 Nav2 控制器向下游发布 local plan / `cmd_vel` 时继续携带旧时间戳的问题。

同时，本版把 v1.1 的“直接用 `odom -> base_footprint` 底盘角旋转速度”改回为“用里程计 yaw 旋转，`gimbal -> chassis` 交给电控板处理”。因此本版不仅是时间戳修复，也是一次速度坐标策略回退。

## 2. 本版要解决的问题

### 2.1 local plan 时间戳过期后，速度同步可能一直卡住

v1.1 的 `localPlanCallback()` 忽略消息内容，只要收到 local plan，就立即把当前时间记为控制激活时间：

```cpp
void FakeVelTransform::localPlanCallback(const nav_msgs::msg::Path::ConstSharedPtr & /*msg*/)
{
  // Consider nav2_controller_server is activated when receiving local_plan
  last_controller_activate_time_ = rclcpp::Clock().now();
}
```

这段逻辑不检查 local plan 自带的 `header.stamp`。只要上游持续收到一条时间已经过期的 local plan，同步路径就会被继续认为是“激活状态”，`cmdVelCallback()` 可能一直把速度留到 `latest_cmd_vel_`，等待 odom/local plan 同步。

v2.0 增加了 local plan 时间戳检查：

- 如果 local plan 时间与当前节点时间相差超过 `CONTROLLER_TIMEOUT = 0.5 s`；
- 打印限频告警；
- 主动把 `last_controller_activate_time_` 推到超时之前；
- 让后续速度直接走“立即转换并发布”路径，不再挂死在同步路径。

### 2.2 控制器使用的 pose 时间戳可能来自旧 TF

Nav2 调用控制器的 `computeVelocityCommands()` 时，传入的 `pose` 可能携带较早的 TF 时间戳。v1.1 原代码直接使用这个 `pose` 做全局路径变换：

```cpp
auto transformed_plan = transformGlobalPlan(pose);
```

并把这个旧时间戳复制给输出速度：

```cpp
cmd_vel.header = pose.header;
```

这会造成 local plan、TF 查询和下游速度同步使用不同的时间基准。v2.0 在控制器内部统一改成控制器当前时钟：

```cpp
geometry_msgs::msg::PoseStamped current_pose = pose;
current_pose.header.stamp = clock_->now();
```

后续 `transformGlobalPlan()` 和输出的 `cmd_vel.header` 都使用这个新时间戳。

### 2.3 本版时间戳改动清单

在 `1.0 → 1.1 → 2.0 → 2.1 → 3.0 → 3.1` 这条相邻版本链中，**2.0 是唯一直接修改时间戳来源和过期判断的相邻升级**；2.1 虽然改了 GICP 的发布线程，但没有重新修改 `map -> odom` 的打戳来源。

## 4. 逐文件修改

### 4.1 `fake_vel_transform.cpp`

文件路径：

```text
nav-master-ccut/src/rm_navigation/fake_vel_transform/src/fake_vel_transform.cpp
```

#### 4.1.1 增加 `<cmath>`

新增：

```cpp
#include <cmath>
```

本版新增了 `std::abs(plan_offset)`，需要该头文件。

#### 4.1.2 统一使用节点时钟

`odometryCallback()` 修改前：

```cpp
if ((rclcpp::Clock().now() - last_controller_activate_time_).seconds() > CONTROLLER_TIMEOUT) {
  current_robot_base_angle_ = tf2::getYaw(msg->pose.pose.orientation);
  updateChassisAngle();
}
```

修改后：

```cpp
const double controller_age =
  static_cast<double>(this->now().nanoseconds() - last_controller_activate_time_.nanoseconds()) /
  1e9;
if (controller_age > CONTROLLER_TIMEOUT) {
  current_robot_base_angle_ = tf2::getYaw(msg->pose.pose.orientation);
  updateChassisAngle();
}
```

原来的 `rclcpp::Clock()` 是临时构造的时钟，v2.0 改为节点自身时钟 `this->now()`。这样，节点时间源、local plan 时间戳和控制器时间戳都落在同一个时间基准上；使用仿真时间时也不容易混用系统时钟。

`cmdVelCallback()` 同样改成预先计算 `controller_age`：

```cpp
const double controller_age =
  static_cast<double>(this->now().nanoseconds() - last_controller_activate_time_.nanoseconds()) /
  1e9;
if (
  is_zero_vel ||
  controller_age > CONTROLLER_TIMEOUT) {
  const double yaw_diff = current_robot_base_angle_;
  auto aft_tf_vel = transformVelocity(msg, yaw_diff);
  cmd_vel_chassis_pub_->publish(aft_tf_vel);
} else {
  latest_cmd_vel_ = msg;
}
```

#### 4.1.3 检测 local plan 是否已经过期

修改前：

```cpp
void FakeVelTransform::localPlanCallback(const nav_msgs::msg::Path::ConstSharedPtr & /*msg*/)
{
  last_controller_activate_time_ = rclcpp::Clock().now();
}
```

修改后：

```cpp
void FakeVelTransform::localPlanCallback(const nav_msgs::msg::Path::ConstSharedPtr & msg)
{
  const auto now = this->now();
  const double plan_offset = static_cast<double>(
    now.nanoseconds() - rclcpp::Time(msg->header.stamp).nanoseconds()) / 1e9;
  if (std::abs(plan_offset) > CONTROLLER_TIMEOUT) {
    RCLCPP_WARN_THROTTLE(
      get_logger(), *get_clock(), 2000,
      "local_plan stamp is %.2f s from now; bypassing odometry/local_plan sync", plan_offset);
    // A stale local_plan stamp can otherwise keep the sync path enabled forever.
    last_controller_activate_time_ =
      now - rclcpp::Duration::from_seconds(CONTROLLER_TIMEOUT + 1.0);
    return;
  }
  last_controller_activate_time_ = now;
}
```

`plan_offset` 的符号含义如下：

- 大于 0：local plan 比当前节点时间旧；
- 小于 0：local plan 的时间在未来；
- 本版使用 `std::abs(plan_offset) > 0.5`，因此两个方向超过 0.5 秒都会被视为不可信。

超时后不是只打印错误，而是把 `last_controller_activate_time_` 设置为：

```cpp
now - rclcpp::Duration::from_seconds(CONTROLLER_TIMEOUT + 1.0)
```

也就是当前时间之前 1.5 秒，确保 `controller_age > 0.5`，后续速度立即走直发路径。

#### 4.1.4 在同步回调里再次拒绝旧 local plan

`syncCallback()` 修改前：

```cpp
void FakeVelTransform::syncCallback(
  const nav_msgs::msg::Odometry::ConstSharedPtr & odom_msg,
  const nav_msgs::msg::Path::ConstSharedPtr & /*local_plan_msg*/)
{
  std::lock_guard<std::mutex> lock(cmd_vel_mutex_);
  // 直接处理 latest_cmd_vel_
}
```

修改后首先检查：

```cpp
void FakeVelTransform::syncCallback(
  const nav_msgs::msg::Odometry::ConstSharedPtr & odom_msg,
  const nav_msgs::msg::Path::ConstSharedPtr & local_plan_msg)
{
  std::lock_guard<std::mutex> lock(cmd_vel_mutex_);
  const double plan_offset = static_cast<double>(
    this->now().nanoseconds() - rclcpp::Time(local_plan_msg->header.stamp).nanoseconds()) / 1e9;
  if (std::abs(plan_offset) > CONTROLLER_TIMEOUT) {
    return;
  }
  // ...
}
```

这样即使同步器仍然配出了一组消息，旧 local plan 也不会继续触发下游速度发布。

#### 4.1.5 最终速度旋转改回里程计 yaw

v1.1 的选择是：

```cpp
const double yaw_diff =
  has_chassis_angle_ ? current_chassis_angle_ : current_robot_base_angle_;
```

v2.0 改为：

```cpp
// The command is expressed in the world-stable fake base frame. Rotate it into the
// gimbal/lidar frame using the odometry yaw; the control board handles gimbal -> chassis.
const double yaw_diff = current_robot_base_angle_;
```

这表示速度先转换到 gimbal/lidar 系，再由电控板完成 `gimbal -> chassis` 的变换。v1.1 中新增的 `updateChassisAngle()` 仍然被调用，但它的结果不再参与最终 `transformVelocity()` 的旋转。

### 4.2 `omni_pid_pursuit_controller.cpp`

文件路径：

```text
nav-master-ccut/src/rm_navigation/pb_omni_pid_pursuit_controller/src/omni_pid_pursuit_controller.cpp
```

#### 4.2.1 给控制器输入 pose 重新打时间戳

修改前：

```cpp
// Transform path to robot base frame
auto transformed_plan = transformGlobalPlan(pose);
```

修改后：

```cpp
// Nav2 may pass a pose whose header stamp was taken from an older TF sample.
// Re-stamp that pose with the controller clock so the local plan, TF lookups,
// and downstream velocity synchronization all use one current timestamp.
geometry_msgs::msg::PoseStamped current_pose = pose;
current_pose.header.stamp = clock_->now();

// Transform path to robot base frame
auto transformed_plan = transformGlobalPlan(current_pose);
```

因为 `transformGlobalPlan()` 使用传入 pose 的时间戳做 TF 查询，使用旧时间戳就会把旧 TF 带入本次规划。

#### 4.2.2 输出速度使用同一时间戳

修改前：

```cpp
geometry_msgs::msg::TwistStamped cmd_vel;
cmd_vel.header = pose.header;
```

修改后：

```cpp
geometry_msgs::msg::TwistStamped cmd_vel;
cmd_vel.header = current_pose.header;
```

这样 `local_plan`、本次路径变换和最终 `cmd_vel` 使用同一时刻，下游基于时间同步的逻辑不会再把旧速度当成新速度。

## 5. 修改后的时间戳链

```text
Nav2 controller_server
  -> computeVelocityCommands(pose, ...)
  -> current_pose.header.stamp = clock_->now()
  -> transformGlobalPlan(current_pose)
  -> local plan 使用当前时间
  -> cmd_vel.header = current_pose.header
  -> fake_vel_transform
       -> local_plan.header.stamp 与 this->now() 比较
       -> 相差超过 0.5 s 则绕过同步，直接发布
```

## 6. 行为影响和版本边界

### 6.1 正确性收益

- local plan 过旧时，不再永久维持同步分支；
- `odometry`、`local_plan` 和控制器输出都尽量使用同一节点时钟；
- 控制器不会继续把旧 TF 时间戳传递到 local plan 和 `cmd_vel`；
- 速度坐标转换恢复到由电控板处理底盘变换的设计。

### 6.2 本版没有改动的内容

本记录未列出的模块，在本版中都没有源码差异，保持 v1.1 原样。
