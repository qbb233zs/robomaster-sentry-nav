## 1. 本版结论

本版分为两部分：

1. **定位稳定性修复**：修改 small-GICP 定位节点的 TF 发布线程和 `result_t_` 并发保护；
2. **2027 赛季 3V3 仿真资源移植**：加入 2027 Gazebo 世界、场地模型、2D 栅格地图和出生点配置。

业务源码共修改 3 个文件，并新增 6 个地图/仿真资源文件：

- 修改：`small_gicp_relocalization.hpp`

## 2. small-GICP 本版要解决的问题

### 2.1 20 Hz TF 定时器可能被 GICP 配准阻塞

v2.0 的 `map -> odom` 发布方式是 ROS wall timer：

```cpp
transform_timer_ = this->create_wall_timer(
  std::chrono::milliseconds(50),  // 20 Hz
  std::bind(&SmallGicpRelocalizationNode::publishTransform, this));
```

与此同时，GICP 配准也由同一节点中的另一个定时器触发：

```cpp
register_timer_ = this->create_wall_timer(
  std::chrono::milliseconds(500),  // 2 Hz
  std::bind(&SmallGicpRelocalizationNode::performRegistration, this));
```

如果 GICP 配准计算耗时较长，回调队列可能被占用，20 Hz 的 `publishTransform()` 就不能按时执行，导致 `map -> odom` TF 更新变慢或出现停顿。v2.1 把 TF 发布移到独立线程，使用 `rclcpp::WallRate(20.0)` 维持约 20 Hz 发布节奏。

### 2.2 `result_t_` 存在跨线程读写风险

`result_t_` 会在这两个位置被写：

- `performRegistration()` 中 GICP accepted 后；
- `initialPoseCallback()` 中收到初始位姿后。

它同时会被 `publishTransform()` 读取。原来没有同步保护。v2.1 加入 `result_mutex_`，所有写入和读取都经过同一把锁，避免发布线程读到正在修改的 Eigen 变换。

## 4. small-GICP 逐文件修改

### 4.1 `small_gicp_relocalization.hpp`

文件路径：

```text
nav-master-ccut/src/rm_localization/small_gicp_relocalization/include/small_gicp_relocalization/small_gicp_relocalization.hpp
```

#### 4.1.1 增加所需标准库头文件

修改前：

```cpp
#include <memory>
#include <string>
#include <vector>
```

修改后：

```cpp
#include <atomic>
#include <memory>
#include <mutex>
#include <string>
#include <thread>
#include <vector>
```

#### 4.1.2 增加析构函数

新增：

```cpp
~SmallGicpRelocalizationNode() override;
```

析构函数负责停止 TF 发布线程并 `join()`，避免节点销毁时后台线程继续访问已经销毁的对象。

#### 4.1.3 增加结果互斥锁

修改前：

```cpp
Eigen::Isometry3d result_t_;
```

修改后：

```cpp
Eigen::Isometry3d result_t_;
std::mutex result_mutex_;
```

#### 4.1.4 用线程替换 transform timer

修改前：

```cpp
rclcpp::TimerBase::SharedPtr transform_timer_;
rclcpp::TimerBase::SharedPtr register_timer_;
```

修改后：

```cpp
rclcpp::TimerBase::SharedPtr register_timer_;
std::thread transform_thread_;
std::atomic<bool> transform_thread_stop_{false};
```

### 4.2 `small_gicp_relocalization.cpp`

文件路径：

```text
nav-master-ccut/src/rm_localization/small_gicp_relocalization/src/small_gicp_relocalization.cpp
```

#### 4.2.1 使用独立线程发布 `map -> odom`

修改前：

```cpp
transform_timer_ = this->create_wall_timer(
  std::chrono::milliseconds(50),  // 20 Hz
  std::bind(&SmallGicpRelocalizationNode::publishTransform, this));
```

修改后：

```cpp
transform_thread_ = std::thread([this]() {
  rclcpp::WallRate rate(20.0);
  while (rclcpp::ok() && !transform_thread_stop_.load()) {
    publishTransform();
    rate.sleep();
  }
});
```

这不是调整 GICP 配准算法，而是把“TF 发布”和“GICP 配准”解耦。

#### 4.2.2 析构时停止线程

新增：

```cpp
SmallGicpRelocalizationNode::~SmallGicpRelocalizationNode()
{
  transform_thread_stop_.store(true);
  if (transform_thread_.joinable()) {
    transform_thread_.join();
  }
}
```

执行顺序：

1. `transform_thread_stop_` 置为 `true`；
2. while 循环退出；
3. `join()` 等待线程结束；
4. 节点析构继续执行。

#### 4.2.3 GICP accepted 时加锁写入

修改前：

```cpp
gicp_correction_ = candidate;
result_t_ = initial_map_to_odom_ * gicp_correction_;
```

修改后：

```cpp
gicp_correction_ = candidate;
{
  std::lock_guard<std::mutex> lock(result_mutex_);
  result_t_ = initial_map_to_odom_ * gicp_correction_;
}
```

#### 4.2.4 发布前复制一份结果快照

修改前：

```cpp
void SmallGicpRelocalizationNode::publishTransform()
{
  if (result_t_.matrix().isZero()) {
    return;
  }

  // ...
  const Eigen::Vector3d translation = result_t_.translation();
  const Eigen::Quaterniond rotation(result_t_.rotation());
}
```

修改后：

```cpp
void SmallGicpRelocalizationNode::publishTransform()
{
  Eigen::Isometry3d result;
  {
    std::lock_guard<std::mutex> lock(result_mutex_);
    result = result_t_;
  }

  if (result.matrix().isZero()) {
    return;
  }

  // ...
  const Eigen::Vector3d translation = result.translation();
  const Eigen::Quaterniond rotation(result.rotation());
}
```

这样发布线程只在锁内复制一次 `result_t_`，后续构造 TF 消息时使用局部副本，既避免数据竞争，也缩短持锁时间。

#### 4.2.5 初始位姿回调同样加锁

修改前：

```cpp
initial_map_to_odom_ = map_to_odom;
gicp_correction_.setIdentity();
result_t_ = initial_map_to_odom_;
```

修改后：

```cpp
initial_map_to_odom_ = map_to_odom;
gicp_correction_.setIdentity();
{
  std::lock_guard<std::mutex> lock(result_mutex_);
  result_t_ = initial_map_to_odom_;
}
```

### 4.3 本版没有改变 `map -> odom` 的打戳来源

2.1 之前代码中已经有以下逻辑：

```cpp
transform_stamped.header.stamp = this->now();
```

以及注释中记录的“不再使用 `last_scan_time_` 打戳”的修复。v2.1 没有改这行，也没有改 TF 的 frame 名称；本版改的是发布线程和并发保护。不要把 9 月 22 日已有的打戳修复误写成 2.1 新增内容。

## 6. 行为影响和版本边界

### 6.1 对定位链的影响

- `map -> odom` 发布从 ROS Executor 定时器改为独立线程；
- GICP accepted 或初始位姿更新时，结果写入受互斥锁保护；
- `publishTransform()` 使用局部位姿快照，避免并发读到半更新状态；
- 节点退出时能主动停止并回收发布线程。

### 6.2 对仿真链的影响

- `gz_world.yaml` 默认世界切换为 `rmul2027_3v3`；
- Gazebo 可以按新出生点生成机器人；
- 仿真地图目录增加 2027 3V3 的 PGM/YAML；
- 新 world 文件可加载 `rm_rmul2027` 场地模型。

这些仿真配置是否被实际启动，还取决于对应 launch 是否读取 `gz_world.yaml` 以及选择的 world/map 参数；本记录只描述压缩包中的资源已存在并已接入配置。

### 6.3 本版没有改动的内容

本记录未列出的模块，在本版中都没有源码差异，保持 v2.0 原样。
